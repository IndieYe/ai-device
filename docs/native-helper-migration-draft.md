# 旧 helper 安全迁移协议草案（未实现、不得部署）

> **状态：历史草案，已被用户确认的手动退休方案取代。** 旧helper仅为测试原型，不实施本草案中的自动迁移；当前约束以 `native-lifecycle-p0-design.md` 的“P1范围调整”和 `packages/device-runtime/native/HELPER.md` 的手动退休说明为准。新job派发仍默认关闭，原包覆盖保护不放宽。

## 范围和结论

目标是把已安装的旧 helper 迁移到支持 job 门禁的版本，且异常中断和重启时不允许旧 helper 与新 job 并行。v17 不检查 job 意图；既有 daemon 锁只在进程存活期间生效。systemd mask 不约束直接执行旧 bootstrap，替换锁路径也无法约束提前打开旧 inode 的进程。不能从新文件已落盘推断旧进程已退出。

本草案不是可执行方案、批准或安全证明。正式派发维持关闭，原包钩子拒绝覆盖保持不变。真实设备停机、服务重启和包变更均需独立授权，本任务只允许隔离设计和验证。

## 受支持的运行边界必须先冻结

迁移安全证明必须列出所有合法启动旧 helper 的入口（systemd unit、安装的包装命令、人工/自动化调用及其权限）。对无法列举的入口、仍可能运行的外部管理器或不可核验的既存旧进程，拒绝迁移；不能假定 unit 是唯一入口。对有权手工直接执行旧代码或修改 root 文件的可信管理员，迁移期间必须有明确的操作排他约定；这是运维前提而非技术围栏。不得把恶意 root 防护作为本项目默认目标，但也不能把实际存在的自动化入口当作不存在。

## 持久迁移记录与失败封闭

独立管理员迁移器必须使用不依赖旧包可执行文件的持久运行时。迁移开始前按无覆盖、fsync 方式保存独立迁移意图，绑定操作 ID、registry 规范路径、旧 unit/入口和旧 bootstrap 摘要、新候选 snapshot 与协议能力、源实例绑定和活动版本、已知未终态台账及迁移版本；不含凭证。意图一旦存在，即使迁移器退出或机器重启，新 job 默认拒绝。迁移日志不能伪造现有 apply-intent，也不删除既有操作记录。

意图只能作为封闭信号，不能证明旧进程受约束。迁移器每一步持久记录前置证据及完成回执；重启后按已验证状态重新对账，不凭阶段名推断副作用完成。未能核对证据、状态冲突、部分写入或回执缺失时保持封闭，由明确管理员对账，不自动重发旧启动、包事务或切换。

## 受控收口和候选切换（待实现）

1. **冻结入口**：对登记的自动启动入口实施可重启后仍生效的封闭，并验证启动配置、持久状态及挂起 job；保证其他受支持调用方也已停止准入。此步不能仅靠 mask 判定全部入口封闭。任何入口无法冻结，停止在意图已持久的封闭状态。
2. **收口旧进程及 sender**：在隔离环境研究受控停止方式；真实服务不得由本任务自动停止。准确核验旧 daemon 所属进程、systemd 活动状态、PID 和 job，并获取原始且 inode 身份稳定的 daemon/execution/package 锁；锁的获取不得被解释为提前打开旧 inode 的进程不存在。必须有能排除所有受支持旧启动者在开锁前已持有旧描述符的机制或维护窗口前提，缺少则不继续。锁取得次序与 helper 现有锁序必须给出死锁证明。
3. **未终态对账**：逐条验证原始 intent、结果、sender 和恢复证据的身份与摘要，处理旧文件名别名；未知、缺失、格式不支持或未证明 sender 后代结束时保持阻塞。任何已执行的操作不得重放或改写成成功。不能仅统计文件或把空扫描视为无操作证明。
4. **切换**：仅在上面前提保持有效的同一互斥窗口中，使用无覆盖/可恢复的发布方式绑定冻结候选和稳定启动入口。不要覆盖正在执行的旧bootstrap或绕过包钩子。记录源、目标和实际变更；重启后重新核验入口、实际运行身份及协议，而不是仅核验磁盘源码。该步骤与发布、真实服务重启、远程操作授权彼此独立。
5. **恢复可用性**：新 helper 的运行代码身份、唯一实例、未终态兼容和跨版本互斥均经验证后，单独评估解除迁移封闭；不能以候选自检、单次 PID 查询或迁移回执作为派发许可。没有明确验证和许可时保持默认拒绝。

## 必须完成的隔离验收

- 真实v17 bootstrap和新版helper，不是仅对mock或锁函数进行测试；覆盖旧daemon先运行、迁移先开始、旧入口迟到启动、锁文件提前打开、daemon退出但sender/后代仍运行。
- 在意图持久、入口封闭、旧进程收口、候选发布和切换的每个边界注入进程退出/重启；重启后观察实际unit、job、PID、入口与持久记录，未能确认均拒绝。
- 代表性旧启动的已确认、unknown、无sender回执、文件名碰撞和不兼容记录；保证不重放、不覆盖、不删除原证据。
- 覆盖旧与新管理器并发、旧dispatcher已运行及响应丢失、迟到worker和包锁争用。检查原包preinst/pretrans保护仍拒绝覆盖，active保持不变。
- 通过所有测试并进行独立审核前，新job派发仍禁用；隔离容器结果不替代目标实机/宿主重启验收。

## 当前阻塞

尚未确定可靠且可验证的机制来排除替换或封闭前已经打开旧锁inode、但尚未取得锁的旧启动者；旧helper不遵守新的持久意图。需要先确定所有受支持入口及其可强制执行的维护窗口，或设计一个对既有旧启动者也有效的受控切换机制并证明其完整性。不要仅增加观察函数或把测试通过当作迁移协议实现。
