# macOS launchd 协调：最小条件与验证计划

状态：待验证设计，不是安装说明或执行授权。事实索引：`client-native-macos-lifecycle-design.md` 末节；需求：`../doc/requirements/client-native-install-upgrade.md` §7、§11。

## 目标与边界

回答一个具体问题：已绑定实例正常退出后，在持续管理/start/runtime 三锁下，能否安全卸载并重新装载本安装的固定 GUI job，且不终止活动任务、不误启动其他身份、不重放未知动作。

不要求所有 loaded effective 属性与 plist 完全等价。也不以 Program/argv 形状、磁盘 plist、runtime 唯一性、无 PID、socket 失败或 print 非零单独授予卸载许可。`procinfo` 是诊断输出，不用作稳定生产接口。

本计划只授权范围内的文档与离线准备；以下真实 job、登录、安装实验均尚未授权。现存产物、临时目录、账户之外资源和服务不得清理或改变。实验结果不能反向扩大原授权。

## 最小条件与证据

| 条件 | 当前证据 | 剩余判据 |
|---|---|---|
| 唯一显式用户和固定系统路径 | 私有登记、账户复核、固定 launcher、磁盘 plist 精确校验 | root/目标用户实际权限待隔离验收 |
| 停止的是取得空闲租约的实例 | 同连接挑战、peer UID/PID/创建时间、原身份退出观察 | GUI job 中真实路径待验；ACK 不等于退出 |
| 退出前无受管活动且退出承诺不可逆 | 调度门禁与有限进程回归 | GUI 启动的完整实例及活动任务组合待验 |
| 后继不能越过程序加载屏障 | 原生 SH start → EX runtime；独占 start 下并发后继不 exec | 登录/KeepAlive 下实际后继与锁对象一致性待验 |
| 卸载不影响仍在执行的受管任务或管理者 | 固定 launcher 门禁前无显式 spawn；外部安装器设计 | job 与 peer 可不同；需具体证明受影响进程范围，不能靠锁推 label 归属 |
| 查询失败和动作结果未知不误推进 | 有界查询与错误闭锁、单次动作设计 | 真实工具退出码/超时及登出竞态待验 |
| 修改程序与服务定义后只启动一次、精确 ready | 内部组合与包树回归 | bootstrap/bootout 协调及生产入口尚未实现 |

受控 launcher 以外的直接模块、旧入口和自定义 job 不能默认为遵守锁前协议。发现它们时须按实际支持契约处理；不能自行缩小需求或静默采纳。RootDirectory 在普通 GUI job 的接受/凭据语义未证，不将理论可能性本身登记为已确认故障。

## 现在可执行的离线工作

1. 冻结准确源码、包 SHA、build_id 和现有证据索引，不再重复同一局部回归获取“整体完成”计数。
2. 准备只读观察/记录格式：每次动作前后记录登记指纹、锁 dev/inode、原 PID/创建时间、目标 domain/label、一次动作与结果。不要记录 token、配置正文或完整 GUI 域输出。
3. 测试编排仅通过替身检查动作顺序、超时、取消和未知不重放；必须明确标记替身证据不能证明 launchd 语义。不得为填齐矩阵新增永远拒绝的空壳生产状态机。
4. 仅在下面实验得到足够对象与进程证据后，才选择最小生产协调实现。没有证据时保持生产写入/卸载入口未开放，不通过额外解析诊断字段补造保证。

## 需另授权的隔离实验矩阵

执行前必须由用户明确批准：隔离 Mac 环境、专用普通账户、测试 job/label、目录、允许的登录操作和服务动作。不得使用当前真实客户端身份或生产 label。必须先有恢复方案和留存空间；不默认授权删除任何测试资源。以下不提供可直接误执行的系统命令。

| 实验 | 观察点 | 通过条件/失败处置 |
|---|---|---|
| 正常 GUI 实例，空闲租约退出 | 原 peer 身份、进程组、三锁和后继 | 原身份退出且受管工作清理；后继不进业务；不得把退出码单独当整体证明 |
| 前台及后台任务忙 | 租约回复、任务持续、准入 | 零卸载/零发布，原任务和准入保持 |
| 手工受管实例占 runtime，loaded launcher 忙退 | socket peer 与 job PID分别记录 | 不强求二者相同；确定 job 后继仅能门禁前忙退及实际卸载影响。无法确定则 unknown，不自动卸载 |
| KeepAlive 重启与同时多次启动 | start 锁持有全程与后继执行位置 | 零新业务/零新 Python 加载越过原生屏障；不能仅凭无 socket 判断 |
| 租约退出前后登出/再登录 | 旧域、新域、单次查询和动作结果 | 不混用两次域快照；任何归属/动作不确定停止且不重放，不安装新树 |
| 明确未登录 | 真实登录状态与受支持域查询对照 | 获得足够依据才实现未登录路径；非零/超时都不能自动归为未登录 |
| 安装器是否属于目标 job/进程组 | 管理者身份及受影响范围 | 卸载不能终止持锁管理者或其必要子进程；普通 PPID/PGID不等于label归属 |
| GUI job 正常退出后的剩余进程 | 同组进程与已批准方案A范围 | 验证 AbandonProcessGroup 等实际效果，不追杀方案A排除的已成功脱离后代 |
| bootout/bootstrap 失败、响应丢失或超时 | 动作受理与后续观察 | 明确 unknown，无自动重试/回滚/覆盖；保留树和锁相关证据 |
| 坏 Python/缺失程序且 socket 不通 | 运行互斥及真实服务状态 | 只有停止与跨实例屏障均证实才允许修复；socket失败不能放行 |

## 如何裁决与推进

- 每次只验证一个假设，保留原始有限日志、准确输入和制品身份；将结果绑定真实入口，不用“测试命令成功”代替语义结论。
- 若受控 job 对象与影响范围可以证明：先实现最小一次性卸载/装载协调及失败闭锁，再独审，最后在获授权环境验证完整 A→B。
- 若只证明部分受控状态：列出未覆盖状态与产品影响，交用户裁决支持范围；不得自主改需求为管理员手工处理。
- 若公开机制与实验均无法形成可依赖条件：明确架构阻塞和最小待决选项，不无限增加属性解析或重复离线原型。
- 标准 payload 所有权警告独立保留 fail-closed；nopayload 检查包无警告不关闭该根因。两类检查包继续拒装。
- 最终完成仍需完整安装、首次配置、忙拒绝、升级、损坏修复、卸载保数据、双平台/中心MCP回归、整体审核及另授权 Mac 提交集成。

## 首批三项实验的具体观察契约

以下是脚本实施契约，不是已有工具或可执行命令。脚本尚未实现，不得把字段齐全当成安全判定器。

### A. 同连接退出及跨实例屏障

- 持锁前提：management/start guards 必须来自本次执行进程成功取得的非阻塞独占 `flock`，全程保留对应 fd、不显式解锁；runtime 在原身份退出后成功取得独占锁并持续保留。`private_lock_matches` 仅核 fd/路径对象身份，不证明 `flock` 所有权或持锁连续性。不得以普通打开的 fd、缓存布尔值或旧进程 guards 代替。进程崩溃后按 C 项重新观察，不沿用原持锁结论。
- 来源：复用 `client-macos-lease-request.m` 的 `lease_request_connected`、`lease_wait_original_exit`；使用 `private_lock_matches` 核对持有 fd 与稳定锁路径，使用登记 guards 核身份前后不变。peer 身份包含 PID 和创建时间，不从 socket 文件名推进程。
- 顺序：先核登记和 management/start guards，再取得同连接租约；busy 原样结束且不产生退出动作；接受退出后观察原身份消失，再取得 runtime 并复核全部 guards。每一项分别记录，不用一个 accepted 布尔值概括。
- 成功：只表示原实例退出且合作启动屏障连续，不包含 job 卸载、域不存在、全部后代消失或 ready。
- unknown：peer 检查失败、连接/ACK 丢失、原身份检查拒绝访问、期限无效、登记或锁对象变化。不得再次连接重发退出；保留已发生步骤并终止写入。
- 可立即离线验证：沿用有限进程和临时锁测试中的 acquire/退出/身份复核接口；实际 GUI job 归属留给实验 B。

### B. 手工 socket 实例与 loaded launcher 后继不同

- 控制输入：在另授权隔离环境中分别启动手工受管实例及专用 label 的固定 launcher，保证使用同一用户、同一配置和同一组锁；不能用生产 label。控制输入本身用于知道测试 job 的构造来源，不把测试来源证明推广到未知生产 job。
- 观察：手工实例 peer PID/创建时间；专用 job 的启动事件；固定 launcher 在锁前/锁后执行位置。若需要记录位置，使用仅实验构建的有限标记写入，不改变生产锁顺序，不在锁前执行网络/子进程。每个标记都声明其为测试 instrumentation。
- 成功：在 EX start 连续期间所有实验后继均止于门禁前且无业务进入；实验卸载不影响管理者、已批准自然继续的脱离后代或其他受管活动。必须分别观察，不用 print 中无 PID 代替。
- unknown：无法观察某后继、标记可能丢失、域切换、管理者归属不清、输出被截断。此时不能继续程序发布。即使实验通过，也须明确生产环境如何取得相应证据；不能将实验标记作为未来稳定系统 API。
- 阻塞裁决：若只能通过实验构造知道 job 来源，而生产入口无法建立必要关系，则报告具体机制缺口。不得添加“job_owned=true”调用者布尔值绕过。

### C. 单次卸载/装载动作结果未知及恢复

- 记录界面：为每次独立实验生成本地实验 ID；动作前记录制品 SHA/build_id、登记摘要指纹、目标 uid/label、guards dev/inode、原 peer 身份及单调时限。只记录必要元数据，不保存 token、配置正文或整个 GUI 域。实验 ID 不是产品升级事务或幂等回执机制。
- 次数：一次实验最多一次请求目标动作；工具失败或超时不换目标、不重放、不自动回滚。区分“未发起”“已发起结果未知”“明确完成”，退出码只作为一项观察。
- 崩溃：原持锁进程死亡后不假设锁连续。新观察进程必须重新读取登记、稳定路径与程序清单，旧 PID/创建时间用于只读比较；不能直接沿用旧 guards 或继续写入。
- 恢复：先封存原实验日志，核对保留程序树与登记；停止任何自动后继动作。若状态不能明确，等待用户批准该隔离实验的具体处置。不得自动清理 stage、旧树、job、账户或锁，不得为恢复实验停止真实服务。
- 解锁实现：只有能够说明每个生产动作的对象证据、失败结果及恢复入口后，才实现相应协调。离线替身仅检查单次请求、边界拒绝与资源释放；真实语义成功必须来自获授权的隔离实验。

### 已确认的本机观测来源限制（2026-11-05）

本机SDK launchctl.1：kickstart -p 成功输出新进程或已运行进程PID；该命令会主动请求运行服务，不是只读job归属查询。只能在另获授权实验的一次启动动作中同时收集PID，不能为退出前归属探测提前kickstart，不得使用-k。PID须与创建时间及该次socket peer观察比较，输出PID本身不证明退出/卸载完成或后继屏障。

list无参输出PID/状态/label，可作人工实验辅助记录；指定label的详细格式未承诺稳定，-x已不支持。手册CAVEATS说明旧子命令（主要list）输出应匹配既往OS X版本；此声明不提供原子job/peer快照或进程连续性保证；新子命令（print）输出明确不构成API，不得包装成稳定生产归属协议。procinfo仍仅诊断。以上命令本轮均未执行，只读手册/SDK。生产退出前job/peer必要关系仍未解决；不新增job_owned布尔门禁或以实验标记替代。此节为新资料补充，未做独立审核，不改变此前已审实验A/B/C契约。

### list调用上下文与PID竞争的实验判据（2026-11-05）

asuser只尽量采用目标用户bootstrap，不切UID/GID；user/gui共享部分名称空间但服务集合不同，不能把asuser UID list label等同精确gui/UID/label查询。获授权实验分别记录执行凭据、已知测试bootstrap来源、目标GUI UID/测试label，以list PID和socket peer PID/创建时间作分时比较；不同或更替时关系保持unknown，两次相同也不证明中间无更替。job PID等于peer不是通用许可条件，手工合作实例与loaded launcher本可不同，仍须独立证明job及卸载影响范围。

实际launcher非阻塞SH start→非阻塞EX runtime→释放start→固定Python；管理者连续EX start只挡后到合作入口，结合EX runtime判断已通过start的交接进程，不能单凭start排除锁前launcher/非合作入口或证明job归属。该路线可作实验，不以缺少原子查询本身断言生产不可行；本次查阅未发现能替代上述前提的公开只读精确GUI job-to-peer方法，不是穷尽证明。ses-14535/msg-1135477限定静态审核完成/drained，未运行系统命令或实验、未重跑测试。新增来源末节经该次核对，旧0517ffd哈希仅对应原冻结版本。

## 首个可实施实验的范围与启动门禁

优先实施B的关系观察，而非先写生产bootout协调器：在获授权的专用GUI账户/测试label/测试目录中，分别构造受控loaded launcher和手工合作实例，观察它们是否确为不同进程，结合连续EX start/runtime验证后继门禁。一个脚本只承担该实验，不含升级发布、PKG安装、账户创建、自动卸载/清理或故障后的重放。list/print只存必要有限诊断片段，配合实验已知的启动来源及PID创建时间；不能输出生产job_owned许可。

编写可执行GUI编排前需要明确：隔离Mac目标与OS/架构、专用普通账户及GUI登录状态、唯一测试label/plist、专用程序/状态/日志目录、是否允许bootstrap/一次kickstart/bootout及其准确目标、允许的正常退出请求、失败后保留与由谁处置。当前这些真实实验目标及动作未获授权，不推定为当前宿主/现有用户/生产label。离线源码授权仍有效，但不据此运行上述动作。

首轮成功标准是产出可复核的两实例关系及合作屏障事实；未能证明关系、PID更替、权限不足或动作unknown就停止该轮并保留资源，不宣称生产卸载安全。获得具体环境授权前不新增仅验证替身顺序的通用框架；已有租约/锁/组合测试继续作为组件证据。本节是实施范围，不是脚本已完成或执行许可。其他独立离线事项不受此实验门禁扩大或授权。

### 首实验时序与观察完整性补充

msg-1135490限定审核认可先B及授权边界，并要求明确两阶段：手工实例持EX runtime期间，管理者仅持续EX start观察，不可能同时取得同一EX runtime；按另获批准的正常退出流程等原身份消失、成功取得并持续持有EX runtime之后，才验证双屏障后续阶段。记录阶段转换，不能混称全程同时持两锁。实施前定义如何识别后继到达/止于门禁、漏记/超时/进程更替及结束条件；没有观察到后继不等于证明后继被阻挡，不能可靠判断则unknown。实验标记不作生产归属许可。该审核已completed/drained，仅静态，无系统实验。
